Image-cache eviction score

Every cached reference image carries a score. When the cache is over its byte budget, the lowest scores are evicted until it is back under. Tune the three weights and watch which images cross the line.

score =  cost.actual1.8  /  (stale + 30d)1.2 cost.actual = measured render seconds · stale = time since last read
Only over budget. Under budget nothing is ever evicted. This is a ranking rule, not a time-to-live — a cold image survives indefinitely while there is room.
Size-independent. An image's byte footprint decides how much evicting it frees, never where it ranks. Every reference image is the same 16 MB anyway.
Days here, seconds in the code. This page works in days for legibility. Converting both stale and s₀ to days multiplies every score by the same constant, so the ordering — the only thing eviction reads — is identical.
evict_cost_weight — how hard an expensive render is protected
evict_decay — how fast value falls once an image goes unread
evict_grace_days — anything read within s₀ counts as fresh
illustrative — how deep the cut reaches into a sampled corpus. Not a settings.json key; real pressure comes from bytes over budget.

settings.json


    

    

      
These three keys live in <cache-dir>/settings.json and are
         hand-edited only. There is no CLI flag for them and the tools never write them
         back — a run reads them and leaves the file alone.

      
budget_gb is the one setting with a CLI surface: it resolves compile-default
         → settings.json → --budget-gb, and
         nbcache --set-budget-gb rewrites that key alone, preserving whatever weights
         you have hand-added here.

      
A mis-ranked image costs exactly one re-render, never a wrong verdict — which is why these
         are tuned by judgement rather than measured to a decimal.
